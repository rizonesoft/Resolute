# Antigravity Output and Safety Rule

- Bound every shell command output (`Select-Object -First` on Windows, `head` or `tail` on WSL, filtered test cases) and redirect full logs to scratch, never the repository: `R:\scratch` on Windows, `/mnt/r/scratch` on WSL (the same folder), or the session scratchpad when one is given; `build/` holds derived project output.
- Treat `git status` as a concurrency lock: never write over unfamiliar uncommitted changes from another session without asking the user first.
- Never use em dashes or en dashes anywhere: prose, code, comments, commit messages and generated files. Use a comma, colon, parentheses or a full stop. Write one line per Markdown paragraph and list item.
- Use atomic temporary-file-then-replace writes for all persistent data files.
- Author and execute TODO work as small, single-responsibility sections with granular micro-step checklist items (`Done when:` and backticked path/symbol per item) toward a 100% complete development plan with zero silent drops or unowned controls.
- End code change reports with a `Layer:` line identifying the owning module.
- Work under the Operating directive in `AGENTS.md`: decide and act, and ask the operator only for what its Safety section lists.
- Under Orchestrator (Carbon), plan one TODO section per `exit_plan_mode` handoff (completing `process-todo-section` steps 1 to 3 against the repository and its design contract, naming exact tokens, shared `Chrome:` controls, states and verification commands), and set `Re-plan if:` so Hydrogen hands back to Carbon (1) after each section's `stamp` and `ci_status.py` check before resolving the next ready row whether `Surface` is `yes` or `no`, (2) when a needed design token or shared `Chrome:` control does not exist, (3) when the pinned reviewer returns `COMPLETION: gaps` or a `P1` or `P2` architectural or design-contract finding, or (4) when Hydrogen fails twice on the same fix.
- Run `python scripts/design-lint.py` before committing UI changes whenever that script is present (strict zero-raw-literal mode on custom token-system apps, theme-only raw-color mode on accepted-look native apps), fix every `file:line` finding with real tokens or theme resources, and never grow a lint baseline with `--allow-add` unless the operator asked.
