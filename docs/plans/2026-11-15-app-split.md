# App split: one repository per tool

Operator instruction, 2026-11-15. Every tool leaves the Resolute repository for its own repository and folder under `D:\Resolute_Bin\<App>`. Resolute becomes the launcher only, and imports the tools from their repositories when a distribution is built. This file is the tracker: work the queue top to bottom, one app at a time, one step at a time, and tick each cell as it is done. A session that picks this up reads this file first and continues at the first unticked cell.

## Decisions (operator, 2026-11-15)

- **Scope:** every tool gets a repository: the 14 merged products that have files today and every plan-only tool (79 tools in all, listed in the queue). The recorded merges stand (four browser tools are Firemin, USBRepair and DVDRepair are DriveRepair, four managers are one).
- **Shared code:** the UI library, lucide, the framework, the repair contract, the CMake policies and the toolchain bootstrap move to their own repository, `Resolute-SDK`, at `D:\Resolute-SDK` beside Resolute (not under `Resolute_Bin`). Each app and the launcher pin it by commit. No app carries a copy.
- **Tech stack:** unchanged from Resolute for every app: C++23 on llvm-mingw, CMake and Ninja, `resolute-ui` statically linked, Catch2, one standalone executable.
- **Licence:** GPL v3 for the launcher and every app. The SDK is MIT (brainstorm decision 47).
- **GitHub:** `rizonesoft/<App>`, created private. The operator makes each public.
- **Distribution:** each app is developed and released standalone and is also bundled with the launcher. Resolute pulls from the app repositories only when a distribution is created.
- **Launcher shortcuts:** every app's unattended campaign shortcuts go in `C:\Users\DerickPayne\Desktop\Resolute Bin`. The SDK's go straight on the Desktop.
- **Fresh designs only (operator, 2026-11-15):** every app, the SDK and the launcher get a new identity: new icon, wordmark, banners and asset set. Nothing is derived from the AutoIt-era icons; those travel with a port under `reference/au3/icons/` only as a record of the shipped tool. The launcher's redesign is icons and assets only: its interface is not redesigned.
- **Checks during the split (operator, 2026-11-15):** Resolute's full gate set is not run per change or per app. A move runs only the quick checks it can break: plan claims, graph validate, plan check, README check, and a build of a touched target when build files changed. GitHub runs the full set on push, and it is run here at most once, when the split is finished.
- **App icons (operator, 2026-11-15):** not standardised into one tile with a glyph. Each app gets its own full-colour icon, drawn for it in its own repository at its step 4, under shared guidance that lives in the SDK's `DESIGN.md`. Lucide stays what it is: the glyph set inside the interface, never an app icon.
- **Clean Resolute:** when an app moves, its AutoIt source, samples and other leftovers leave Resolute in the same pass.

Supersedes brainstorm decision 34 ("every tool lives at `extensions/<Tool>/`") and the "tree has no external dependencies" rule as far as the SDK pin goes. Cost of reversing: copy an app's tree back under `extensions/` and delete its repository.

## The seven steps, per app

Do them in order. Steps run in order within an app. Across apps, steps 1 to 4 run ahead for the next apps while earlier ones wait on the operator at step 4 (operator, 2026-11-15: "why did you stop?"); steps 5 to 7 follow each answer. **Unit 0, the SDK, goes first** (operator, 2026-11-15): every app pins it, so no app goes past step 1 before the SDK's commit exists.

1. **Move.** Steps 1 to 3 are scripted: `& tools\app-split\new-app.ps1 -Name <App> -Au3 <tool>[,<tool>] -Goal ... -Acceptance ... -Description ...` from PowerShell in this repository (never through `pwsh -File`, which splits the tool list). What follows says what it does and what is left to the session. Create `D:\Resolute_Bin\<App>`. Copy the app's files out of Resolute into the layout below, then `git rm` them in Resolute. Remove what the move leaves behind (AutoIt examples, sample folders, icons, update files, the README gallery row in `docs/readme/tools.json`). Mark the app's Resolute plan sections `Moved:` to the new repository. Run Resolute's plan gates and fix what the move broke.
2. **Repository.** `git init -b main`, add `LICENSE` (GPL v3), `README.md`, `.gitignore`, `.gitattributes`. `gh repo create rizonesoft/<App> --private`.
3. **Kits.** From `D:\Conclave-SDK`: `python forge.py init <dir> --kit todo --kit reviewer --kit toolchain-cpp --kit lsp --goal "<one line>"`. Copy the campaign launcher and its icon renderer from `tools/app-split/` and `scripts/sdk.ps1` from Resolute into the app's `scripts/`, write `sdk.json` with the SDK commit Resolute pins, and write `.conclave/campaign.json` (name, icon, `shortcut_dir`). Run `forge.py check` and `doctor`. The shortcuts themselves are written in step 5, once the icon exists. The kit's commit hook refuses a commit until the plan tree exists, so the first commit after this step is step 7's.
4. **Design.** Three icon directions, free-standing and full colour (`sdk/DESIGN.md` section 14); the wordmark and both banners follow from the icon. No interface directions: the window is the suite's Sidebar tool window (`sdk/DESIGN.md` section 16, operator 2026-11-15), the session proposes the app's sections in its `DESIGN.md`, and the interface is fine-tuned in the app's repository as it is built. Publish the icons as one comparison board per app (a page per app, three columns, light and dark grounds, small sizes), then ask the operator in session with `AskUserQuestion`, multiple choice, the recommended option first, up to four apps per call. **That app stops here until the operator answers; the session does not.** It takes the next apps through steps 1 to 4 meanwhile, so one answer unlocks several apps.
5. **Import the design.** Steps 5 and 6 are generated from one spec per app: `python tools/app-split/finish-app.py tools/app-split/specs/<App>.json` writes `brand/build.py`, `DESIGN.md`, `README.md`, the reference README, the project section of `AGENTS.md` and the plan, leaving alone any file the app already has. What follows says what they are. Put the chosen direction's assets in `brand/` (SVG sources, PNG renders, `.ico`), wire the README banner, write the campaign shortcuts (`pwsh scripts/start-run.ps1 -InstallShortcut`), and write `DESIGN.md`: the app's brand guide plus the rule that every surface answers to the SDK's design contract.
6. **Plan.** Fill `todo/` with small sections of micro-steps from what is known: the app's Resolute plan sections, its AutoIt source, the basic features. `python scripts/todo-graph.py validate` clean, plan synced.
7. **Commit and push** the app repository. Commit and push the Resolute side of the move. Tick the row. Next app.

### App repository layout

```
<App>/
  README.md  LICENSE  AGENTS.md  DESIGN.md  sdk.json
  src/            the C++ tool
  resources/      icon and embedded resources
  tests/          Catch2 suites and fixtures
  brand/          the chosen design: sources and renders
  reference/au3/  the frozen AutoIt source, shipped files and icons (ports and intake only)
  todo/           the plan
  scripts/ docs/ .claude/ .agents/ .codex/ .conclave/   from the kits
```

`sdk.json` names the SDK repository and the pinned commit.
