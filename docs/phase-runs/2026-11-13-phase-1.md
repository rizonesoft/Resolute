## Lessons

- A surface specification is reviewable only when it ends in a matrix of checks the build must pass; without it the reviewer rightly refuses "specified" as proof.
- A message that promises something (a folder "made again") is a behaviour somebody must build and check; the factual wording needs no owner.
- When a record's rounds keep finding contradictions in one rule (here, when a saved setting reaches the running tool: four findings), replace the rule with one that cannot contradict itself (reconcile effective against target) instead of adding exceptions; the next round was clean.
- The dispatcher keeps one writer model per record. When the operator changes the model mid-section, stop the record with a note and continue on a new record under the new model, reviewing the whole deliverable again.
