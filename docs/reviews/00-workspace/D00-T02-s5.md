## The three questions

**Does it make sense?** Yes, after five rounds cut it down to what headless can honestly cover. The section was written to cover six behaviors that do not exist in coverable form (a high-contrast override nothing implements, a crossfade delivery that needs a message loop, tick delivery, list filtering, toolbar overflow, settled collapse widths), and every one is now either narrowed in its item with the per-API reason or uncovered with its owner-to-be filed.

**Is it logical?** Only after round two. The suite carried manager-held `[this]` lambdas past every controls case's teardown, and the record claimed the cases shared no state while the manager accumulated dead subscriptions. The RAII drain closes it, and the random-order runs prove no case depends on another's leftovers.

**Did it break anything else?** No. 69 ctest cases pass where 36 did before the section, the tidy count is back at baseline 169 with zero findings in the touched TU, and every gate is green. The only behavioral change outside `tests/` is none: the diff touches the suite and the plan record, and the library is byte-identical.

## Findings

### F1 -- forcing high contrast was demanded, and no override exists to verify -- adversarial -- CORRECTED in `9fa74b7` (independent)

Round 1 asked for high contrast to be enabled and the palette override verified. Enabling it would change the operator's machine, which a test must never do, and there is no override: `Theme::IsHighContrast()` has no caller in `shared/resolute-ui/src/`. The item is corrected to pin the query's live agreement, with both reasons recorded.

### F2 -- the crossfade endpoint was covered as blend math, not delivery -- test-coverage -- CORRECTED in `9fa74b7` (independent)

Round 1 observed that transition state and completion can regress undetected, which is true: `LerpColor` at t=0, 0.5, and 1 is covered, delivery across frames is not, because only the manager's timer completes a transition. The item is corrected to the blend-math scope, and delivery sits in Uncovered with its reason rather than claimed.

### F3 -- the controls item was ticked while three behaviors sat in Uncovered -- record -- CORRECTED in `9fa74b7` (independent)

The item named list filtering, toolbar overflow decisions, and sidebar collapse thresholds, and all three were uncovered: ListView exposes no filter API and the sidebar's `ApplyFilter` is private, overflow lives in the private `m_overflowStart`, and `TargetWidth()` rides the collapse animation. The item is corrected with the per-API reason, and what is covered instead (selection, sort, badges, toggle, empty states, scaled sizes) is named.

### F4 -- the manager test counted subscribers but never delivered a tick -- record -- CORRECTED in `9fa74b7` (independent)

Tick delivery needs the manager's timer, a message loop, so the item's "shared clock delivering ticks" was unprovable headless. The item is corrected to subscribe and cancel accounting, and the test was strengthened in the same commit: single-cancel routes by id (2 to 1, still animating) and the animating flag is pinned at both ends.

### F5 -- the checkpoint's three failures were asserted, never quoted -- record -- FIXED in `9fa74b7` (independent)

The checkpoint demands a wrong token mapping, a wrong easing value, and an unknown icon name, each failing by name. All three were driven and are quoted in the section: `1973790 (0x1e1e1e) == 1973791 (0x1e1e1f)`, `0.125f is within ... of 0.12600000202655792`, and `nullptr != nullptr` on the flipped guard. Each break was reverted after capture.

### F6 -- three easings had no midpoint pin -- test-coverage -- FIXED in `73603b9` (independent)

Round 2 found `Linear`, `InOutQuad`, and `OutBack` tested everywhere except the midpoint the item promises for every easing. All three are pinned now (`0.5`, `0.5`, `1.0876975f`), with `InQuad` and `OutQuad` midpoints cross-referenced from the Known test, so every easing in `resolute/animation.h` has one. The sweep was verified complete against the header's thirteen easings.

### F7 -- controls cases left manager-held `[this]` lambdas behind at teardown -- integration -- FIXED in `73603b9` (independent)

The round's worst finding. `Select`, `SetSortColumn`, `SetCollapsed`, `ShowEmpty`, and `ShowError` all arm manager animations capturing `[this]`, the singleton manager outlives the stack control, and headless the timer never fires, which made the dangling latency invisible rather than absent. Every controls case now carries a `DrainAnimations` guard declared after its control, so the manager drains before teardown even on a `REQUIRE` failure.

### F8 -- the record claimed the cases share no state -- record -- CORRECTED in `73603b9` (independent)

F7's twin: with dead subscriptions accumulating in the manager, "share no state" was false as written. The sentence now claims what the random-order runs prove (no case depends on another's leftovers) and names the guard that makes it true.

### F9 -- covered behavior was listed as uncovered, and a read as a write -- record -- CORRECTED in `73603b9` (independent)

The Uncovered list named `ReadSystemAccent` (whose wiring the accent test covers) and described `IsHighContrast` as a write mutating shared globals (it is a read). The entry now names `Theme::Init` and the accent lightness math, with the wiring and the read recorded as covered.

### F10 -- two comments described code other than what followed them -- consistency -- FIXED in `1de9d3c` (independent)

The sign-off round found the icon-color comment denying any test calls `ReadSystemAccent` (the accent test does) and the `IsDarkMode` comment sitting above the accent test (an insertion misplacement). Both fixed: the first rewritten around the restoring guard, the second moved above the test it describes.

### F11 -- palette save and restore was hand-rolled, not RAII -- integration -- FIXED in `1de9d3c` (independent)

An advisory from the sign-off round, fixed in the already-owed re-round rather than filed: any non-returning exit between the save and the restore would have leaked the live accent into the pinned defaults. `RestorePalettes` restores on unwind, and trailing checks prove the restore ran.

### F12 -- the checkpoint command itself was never quoted -- record -- FIXED in `1de9d3c` (independent)

The evidence quoted `check-all` and the direct binary run but never the literal `ctest --preset debug -L ui`, leaving the label wiring the correction rests on unproven. It now reads `100% tests passed out of 42`, exit 0: 42 selected, not zero.

### F13 -- the TU relied on transitive includes for Win32 and wide strings -- consistency -- FIXED in `96988df` (independent)

`RGB`, `RegGetValueW`, `HIGHCONTRASTW`, `HBITMAP`, and `std::wcscmp` all arrived via `resolute/*.h`, so a header trim in the library would have broken the test TU rather than the library. `<windows.h>` and `<cwchar>` are included directly.

### F14 -- the edit-sessions item died before the view borrowing it -- integration -- FIXED in `96988df` (independent)

Destruction order was `item`, `drain`, `lv`, so the installed provider outlived its referent through `~ListView`: the same lifetime inversion `DrainAnimations` was added to close. `item` is declared first now, and the capture narrowed from `[&]` to `[&item]`.

### F15 -- the tidy citation rotted when the guard moved the line -- record -- CORRECTED in `96988df` (independent)

The evidence cited the `bugprone-signed-bitwise` finding at line 109, but the `RestorePalettes` insertion had moved the expression to 120 (and the direct includes to 123). Re-resolved to the expression's current line. Line citations rot on every edit; this one rotted twice in one review.

### F16 -- the collapse case checks a value against itself -- test-coverage -- filed as D00 T02 §6 (independent)

Round 5, at the hard cap: `CHECK(bar.TargetWidth() == bar.ScaledWidth())` cannot fail, because `TargetWidth()` is defined as `return ScaledWidth();`. It proves nothing about collapse width. Per the hard-cap exit the fix is tracked work, not dropped work: D00 T02 §6 deletes the line, and the stamp names the filing.
