## The three questions

**Does it make sense?** Yes. Four checks now exist where prose was trusted, and each was proven able to fail before being accepted as passing.

**Is it logical?** After two rounds, yes. The floor is a whole-plan figure and now applies only to a whole-plan scan; the claim total and the hold count no longer contradict each other; the staleness filter belongs to git rather than to the filesystem.

**Did it break anything else?** The Items column change touches `plan --sync`, which every section depends on. It rewrites the cell in place, exactly as the box character already was, so the table's alignment survives: verified on rows that grew a digit (`D07 T01 §3`, 6 to 12) and on rows that shrank one (`D05 T07 §9`, 10 to 6). 400 graph self-tests stay green.

## Findings

### F1-F4 -- raised by the independent review, all four correct -- FIXED in `6cb2e1b`

Recorded in full in the commit message. In summary, each was probed against the code before being accepted:

| # | Defect | Probe that confirmed it |
| --- | --- | --- |
| F1 | the coverage floor was bypassed when no claims remained | a zero-claim tree exited 0; deleting every claim made the gate pass |
| F2 | deleted sources were filtered out before the git check | `.exists()` dropped them, and a deleted cited file is the strongest staleness evidence there is |
| F3 | the whole-plan floor was applied to a `--root` subtree | `--root todo/01-framework` reported four claims holding and exited 1 |
| F4 | a malformed claim counted as holding | printed `1 claim(s) -- 1 hold, 0 stale, 1 malformed` |

**F2's fix proved itself on the live tree.** Once the filter became git's rather than the filesystem's, `D00 T03`'s block was immediately flagged on `exokit/` and `shared/exo-ui`, both of which `§3` renamed out of existence. Those are precisely the citations the old code discarded, and they are the best evidence that block needs re-reading.

### F5 -- the default run paid for an analysis it did not use -- performance -- FIXED

Found in this review by measuring rather than reading. `todo-claims.py` with no flags went from fast to **2.7 seconds**, because it called `run_coverage`, which shells out to git once per cited path: 74 subprocesses on today's tree, and that number grows with every TODO added.

That matters because this is the frequently-run gate. A check that costs three seconds gets run less often than one that costs none, and a check nobody runs is a check that does not exist.

The floor needs only claim counts, which are free. The date comparison is the entire cost and belongs to the mode that asks for it. Splitting them:

```
todo-claims.py --quiet              2.7s  ->  0.2s
todo-claims.py --coverage --quiet   2.6s  ->  2.6s   (unchanged, and deliberate)
```

### F6 -- the section's own block had gone stale -- record -- FIXED before implementation

Noted because it is the argument for the section rather than an aside. `D00 T04`'s `Current state` block said "11 claims live" against 30, and "393 cases" against 400. A block describing staleness detection had gone stale.

Both figures were removed rather than corrected, and the same reasoning removed the hardcoded self-test counts from `AGENTS.md`. A figure duplicated in prose is a second source of truth, and the tools already report it.

## What the section asked for that could not be built

The wiring item said "wire into `scripts/check-all.ps1`". That script does not exist; `D00 T01 §5` builds it. `AGENTS.md` rules that a checkpoint citing a gate that does not exist is unfalsifiable and not allowed.

Rather than tick it on a promise, both exit conditions were proven standalone and registered as an item on the section that owns the script. The item text says why, so the next reader does not re-litigate it.
