## The three questions

**Does it make sense?** Yes. Item 1 implements exactly the fix F10 prescribed (stop at the hunk body); item 2 rewrites the two prose surfaces the residual clause lives in. No widening: combined-diff handling stays §12's owned work, and no other rename behavior is touched.

**Is it logical?** Yes. The break sits after the `diff --git` capture (a block opens with its diff line, so it is always found first) and before the rename match. A git header never opens a line with `--- `, `+++ `, or `@@`, and git emits the rename pair above the hunk body, so git-emitted manifests are byte-identical and only pasted post-hunk pairs change behavior. Pure-rename blocks without hunks never hit the break (the pre-existing authoritative-rename case pins that).

**Did it break anything else?** No. The only consumer is `build_manifest`, whose output on git-emitted input is unchanged by construction; the self-test suite passes 30 of 30 including the pre-existing rename, grammar, prose-trap, and preamble cases.
