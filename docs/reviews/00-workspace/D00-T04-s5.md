## Findings

### F1 -- the section's own premise was wrong, and the advisory was mostly right -- record -- CORRECTED before implementing (self)

This is the finding worth keeping, because I filed the section myself during a groom pass one turn earlier.

It asserted that four shipped sections could not clear their advisory because the matcher could not see capability that was genuinely delivered, and that the fix therefore belonged in the instrument. Judged against what each kind actually means, **three of the four were bad anchors**:

| anchor | kind | verdict |
| --- | --- | --- |
| `D00 T03 §4` | `document` | anchored on "Correct the Stale Documentation", which is repository prose. The kind means an artifact a user carries. |
| `D00 T04 §4` | `document` | anchored on a critical chain printed to a terminal. |
| `D00 T04 §3` | `list` | its table is already claimed by `reporting @ §3`. One behaviour, two kinds. |
| `D00 T04 §2` | `audit` | a real miss. A review-finding ledger **is** an audit record. |

**The filing had a motive for its error.** It was written immediately after four sections in which a tool of this project reported success while doing nothing, and it pattern-matched a fifth onto that story without testing the alternative. The groom pass that produced it had the evidence available and did not look: judging four anchors against their kinds took one pass and inverted the conclusion.

### F2 -- the compound `document` rule was accused and is correct -- source-defect -- CORRECTED in the plan (self)

The section called the compound rule "the sharpest case", because a section titled "Correct the Stale Documentation" that uses the word six times does not clear it.

That is the rule working. `document` means an artifact a user carries away, and if the bare word sufficed, every TODO that mentions its own documentation would claim a user-facing document it does not have. **Kept, dated, with the reason**, and the misclassified section fixed by correcting its declaration instead.

Worth recording as a near miss: loosening that rule was one of the four items, it was the change the section was steering toward, and it would have made the number fall while making the check mean less.

### F3 -- one message covered three defects and asserted what it had not tested -- correctness -- FIXED in `625f3dc` (self)

The surviving defect, and the one that caused F1.

`applicable kind has no implementing owner` was emitted for an anchor naming a nonexistent section, for an anchor naming a real section whose prose missed the vocabulary, and for a declaration with no anchor at all. All three read as a statement about **ownership**, when what was measured was a regex over a Markdown body.

Now three codes, `anchor-unresolved`, `anchor-unmatched`, and `unowned`, each naming what to do about it, and each `anchor-unmatched` message naming the vocabulary that was searched for:

```
audit: anchored section does not read as 'audit': D00 T04 §1 -- either it is
the wrong anchor, or the section delivers audit without using the words
audit/ledgers/history/timeline/actor/per/...
```

That last clause is what would have prevented F1. A reader who can see what the check wanted can tell a wrong anchor from a missed match in seconds.

### F4 -- a citation that resolved to nothing, in two source files -- consistency -- FIXED in `625f3dc` (self)

`scripts/todo-adjacency.py:5` and `scripts/todo-validate.py:468` both cited "D00 T03 section 19" as the recorded decision that keeps semantic warnings out of the structural ratchet. `TODO-03` has four sections, and **no TODO in this tree has fifteen or more**. ### F5 -- the vocabulary helper printed regex, not words -- design -- FIXED before committing (self)

Found by reading the first output. Extracting `[a-zA-Z]+` from the keyword patterns surfaced the suffix fragments of optional groups, so `print(?:able|ing)?` contributed `able` and `ing` to a list meant to tell a reader what the check wanted. Filtered.

Small, and the point of a message that names what it searched for is defeated by naming things that are not words.

### F6 -- my own measuring instruments failed three times -- record -- ADVISORY (self)

Not a defect in the candidate. Recorded because the pattern is now consistent enough to be worth stating.

- A character class written through a non-raw string became `[a-z][a-z'\]*` and raised `PatternError` at import. Loud, caught immediately.
- `plan --check | tail -2; echo $?` measured `tail`'s exit code and reported 0, which briefly looked like a check that prints `::error::` and exits successfully. The real exit code is 1. **Silent, and it invented a defect that did not exist.**
- The first `--json` reading assumed `kinds` was a list of pairs and produced `anchored applicable kinds: 0`, a clean and completely wrong number.

Two of the three produced plausible wrong answers rather than errors, which is the same shape as `§3`'s baseline parser and `§4`'s stale evidence table. The instrument that nearly cost something here was the one that measured the wrong process's exit code.
