## The three questions

**Does it make sense?** Yes. The launcher and the shared library were compiled with **no warning flags at all** before this section: `-Wall` existed only inside `extensions/RegStudio`, per target, twice. The gate now covers every target the project owns and cannot be missed silently.

**Is it logical?** After one correction. The load-bearing decision is that the policy is applied per target rather than inherited, because a `FetchContent` dependency is an ordinary subdirectory of this build and inheritance is precisely what reaches it.

**Did it break anything else?** No. Release and debug both build clean, RegStudio builds clean standalone through its own script, the import table is unchanged at 23 with no compiler runtime, the binary is unchanged at 2,512,384 bytes, and the launcher runs and answers.

## Findings

### F1 -- the baseline was measured by an instrument that dropped a whole category -- correctness -- FIXED in `8dcb167`

Raised by the independent review as a **P2**, and it is the most useful thing in this section.

The baseline shipped as **52**. The documented procedure yields **59**. The seven missing findings were every `clang-analyzer-*` diagnostic: four `security.ArrayBound`, two `deadcode.DeadStores`, one `optin.performance.Padding`.

**They were in the log the whole time.** The counting script matched the check name with the character class `[a-z0-9,.-]+`. Analyzer checks are spelled `clang-analyzer-security.ArrayBound`, with uppercase letters. Every one failed to match and was dropped.

**The failure mode is what makes this worth writing down.** A parser that drops a category does not error; it reports a smaller number that looks entirely reasonable. Nothing in the run flagged it, and the total was plausible enough that I published it. Had it shipped, the ratchet's first honest run in `D07 T01 §2` would have measured 59 against a baseline of 52 and failed this unchanged tree as a regression, and the obvious suspect would have been the code rather than the baseline.

The trap is now recorded in `todo/.tidy-baseline` itself, because `D07 T01 §2` has to write this same parser against the same output.

**This is the third measurement instrument in this file to fail silently**, after the cp1252 decode that turned every section marker into mojibake and made calibration read all zeros, and the partial `rm -rf` that gutted a compile database mid-run and produced a confidently wrong 36. All three produced plausible numbers rather than errors. The pattern is now explicit enough to state: **a measurement that cannot fail loudly needs a second measurement that disagrees with it**, and here that second measurement was the reviewer.

### F2 -- the third-party exemption and the section's own Done-when were in direct conflict -- consistency -- CORRECTED in the plan before building

Found in validation, before implementing. The first item asked that a new target "with no extra configuration" **inherit** the warning level. The second asked that third-party code be exempt **by construction**. Inheritance is a directory-scoped `add_compile_options`, and a `FetchContent` dependency is a subdirectory of that same scope, so the one mechanism the first item names is the one thing that defeats the second.

Resolved toward the exemption, because it is the property that degrades silently: a missed target of ours produces an unchecked file, while an inherited `-Werror` in a dependency produces a broken build nobody can fix without hoisting the fetch.

The first item's intent was kept and delivered by a stronger mechanism: `resolute_assert_warnings_complete()` fails the configure naming any target that never got the policy. Inheritance can be overridden by a target that sets its own options; an audit of what was actually applied cannot. Proven both ways, including the falsifiability half.

### F3 -- the 93 lunasvg warnings were an artifact of my own probe -- record -- corrected during implementation

Found when the first clean build under the shipped policy reported **0** warnings from `_deps` rather than 93.

The measurement was taken with `-Wall -Wextra` applied at the **root**, which lunasvg inherited. That is the exact mistake the policy exists to prevent, so the number was never describing lunasvg's own build; it was describing what happens when the policy is written the wrong way.

It also invalidated the proof the checkpoint was going to use. "Leave lunasvg's 93 warnings in place while the build succeeds" cannot be run when there are no 93 warnings. Replaced with a better proof: the **identical** `int deliberately_unused = 42;` compiled in `src/main.cpp` and in `lunasvg.cpp`, failing on one side and passing on the other. Holding the code constant and varying only which side of the line it sits on is a sharper instrument than counting a dependency's noise.

### F4 -- the section was written against a toolchain that no longer exists -- record -- CORRECTED before implementing

Two items and the checkpoint named **vcpkg** and **wxWidgets** as the third-party code to exempt. `§2` settled that neither exists. Corrected to lunasvg throughout, and the substitution is not cosmetic: a package manager's exemption is configured per package, while `FetchContent` brings the dependency in as a subdirectory of the same build, so the exemption has to come from not applying the policy rather than from turning it off.

Also corrected: "the placeholder target", which is stale, and the release preset exporting no compile database, which meant `clang-tidy` could not run against release at all.

### F5 -- an unsourced figure that read as a measurement -- record -- CORRECTED by removing it

The opening sentence claimed the AutoIt tree "carried 45 to 68 warnings per tool for years". The range appears nowhere else in the tree, has no recorded source, and cannot be re-derived: checking it needs `Au3Check.exe` and an AutoIt toolchain, neither bootstrapped by `reskit` nor present here.

Removed rather than softened. The argument does not depend on it, and an unsourced number that reads as a measurement is worse than none, because the next reader cannot tell it was never measured.

### F6 -- 91 percent of the first baseline was one style check -- design -- CORRECTED in `.clang-tidy`

`misc-const-correctness` produced **524 of 577** findings, every one "this local could be `const`". A baseline that is nine parts one style check is a baseline where a real regression is invisible, which inverts what the ratchet is for.

Excluded on the config's own stated principle, defects rather than style, the same ground `readability-*` is excluded on. Recorded in the file as a decision with a price: re-enabling it means making `const` a suite-wide convention and fixing 524 sites, not flipping a line.

### F7 -- two claims went stale from this commit -- consistency -- FIXED in `cbd5164`

Caught by `todo-claims.py`, which is the system working. The lunasvg mention count moved 6 to 7 from a comment this section added.

The second is more interesting. `lines src/main.cpp = 573` broke because this section removed an MSVC-only pragma. The sentence it supports is inside a **`Current state (verified 2026-09-16)`** block describing the intake, and it was true on that date. Rewriting the number to 572 to make the claim pass would have quietly falsified the historical record, and this claim will break again on every future edit to that file, inviting the same quiet falsification each time.

Fixed by stating both frames in the prose, the intake number and today's, so the claim tracks the live file while the snapshot stays honest.

## What the 13 warnings actually were

None was a logic bug, and the interesting part is that four of them looked like one. `fontSize` was computed via `Dpi::ScaleF` and discarded in four places, which reads exactly like DPI scaling that was calculated and never applied: a real defect, and text that does not scale.

It is not. Every draw path calls `Typography::Format(..., m_dpi)`, which carries the DPI itself. The locals are leftovers from the approach Typography replaced. The same held for `hovered` and `pressed` in the toolbar, superseded by the animated `m_hoverAlpha` and `m_pressScale` the draw path actually reads, and for `labelBrush` in the sidebar, superseded by `animTextBrush`.

**Checking was the difference between deleting dead code and deleting a feature.** Two of the thirteen were not simply dead:

- `m_tooltipHwnd` is a placeholder for tooltip work that has a real owner in the design-system TODO. Deleted, because an unused member is not a design and the owning section will declare what it needs.
- `#pragma comment(lib, "shell32.lib")` is an MSVC directive clang ignores, so `shell32` was arriving only through mingw's default library set. Now named in `src/CMakeLists.txt`, which makes a real dependency visible instead of incidental.

## Independent review

`codex review --commit cbd5164` (gpt-6-astra, high effort) returned **one P2, and it was right**.

Its advantage was the same as in `§1` and `§2`, and it is worth naming now that it has happened three times: **the reviewer ran the thing rather than read it.** In `§1` it removed only an executable and left the attestation. In `§2` it configured an extension the way its own script does. Here it executed the documented reproduction procedure and got a different number than the one recorded from my own run.

That is a specific and repeatable division of labour. Auditing my own instruments is reliably weaker than writing them, and all three of this file's silent measurement failures were caught by something outside the script: a `repr()`, a rebuild, and now an independent count.

Process note: this commit reviewed in a single invocation, unlike `§1` and `§2` which each needed three. This commit is smaller, which matches the size hypothesis both earlier sections recorded.
