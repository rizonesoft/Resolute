## The three questions

**Does it make sense?** Yes, and the section's premise was measured rather than assumed: querying the three release APIs again returned exactly the versions the table recorded. A section about pins going stale is the last place to take a recorded figure on faith.

**Is it logical?** After one round. The load-bearing decision is that a pin is a dated decision rather than a permanent one, and that falling behind has to be visible in the gate a push already owes rather than in somebody's memory.

**Did it break anything else?** No. Eleven gates pass, the launcher runs, the imports are unchanged, and a bootstrap from a deleted `reskit/ninja` leaves `git status` clean.

## Findings

### F1 -- established facts were discarded when a different lookup failed -- correctness -- FIXED in `d0c8441` (independent)

Raised by the independent review as a **P2**, and it is the mirror of the defect this script was written to avoid.

The script was built carefully so that "could not reach the API" would never be reported as "pin is behind" or as "current", because asserting what a check never established is the defect `D00 T04 §5` had just finished fixing. It got that half right and then threw away the other half: with one component unreachable and another **confirmed** behind, the early `exit 2` fired first and the confirmed finding was never printed. The combined gate showed only the generic unreachable line, and a known stale pin vanished.

Reproduced by the reviewer with mocked responses, and re-driven here with `cmake` pointed at a nonexistent repository while `ninja` sat at `1.0.0`:

```
toolchain-latest: ninja is behind, pinned 1.0.0, latest 1.13.2
toolchain-latest: could not reach upstream for cmake. Currency is UNKNOWN, not current.
exit 2
```

Established facts are reported before unknowns; the exit code still says 2, because overall currency genuinely is unknown.

**The lesson is narrower than "report more".** Being careful about one direction of a reporting defect is what made the opposite direction invisible. I wrote three paragraphs of comments about not asserting unestablished facts and none about not discarding established ones.

### F2 -- my fix for F1 printed `System.Object[]` -- design -- FIXED before committing (self)

Found by reading the gate's output rather than by any check.

`$tcStatus, $tcDetail = switch (...) { 2 { 'unknown', (@(...) + $x) -join '; ' } }` does not do what it looks like. In PowerShell `-join` binds across the comma rather than to the parenthesised expression, so the two-value assignment collapsed into the single string `unknown; System.Object[]` and the gate printed it.

The detail is now computed outside the switch. Recorded because the failure was silent in the sense that mattered: nothing errored, a row appeared, and it took reading the row to see it was nonsense.

### F3 -- the version table was re-measured rather than trusted -- record -- CLEARED (self)

Not a defect, recorded because it was the first validation step and could have been skipped.

The table was written earlier the same day and states the gap this section exists to close. Querying `mstorsjo/llvm-mingw`, `Kitware/CMake` and `ninja-build/ninja` returned `20260908` (2026-09-08), `v4.4.3` (2026-08-25) and `v1.13.2` (2025-11-20), matching every figure. In a section about recorded numbers going stale, taking its own recorded numbers on faith would have been the joke writing itself.

### F4 -- the size baseline named a figure its own source superseded -- record -- CORRECTED before implementing (self)

An item asked that the post-bump binary be quoted "against the 1.39 MB figure `§2` records". `§2` records **2,512,384 bytes** as the baseline, in those words, and lists 1,423,872 bytes as the **pre-intake** `ExoSuite.exe` that figure replaced. Measuring a post-bump launcher against a number from before the intake compares two different products.

### F5 -- a network check was being wired into a gate that must work offline -- adversarial -- CORRECTED before implementing (self)

Two items added `scripts/toolchain-latest.ps1` and put it in `scripts/check-all.ps1`, and neither said what happens on a machine with no network. "Warning, not a failure" does not cover it: an unreachable API is not a pin being behind, and reporting one as the other asserts what the check never established.

Corrected in the plan first, which is why the script has a distinct exit 2 at all, and why F1 was a partial-failure bug rather than a total absence of the case.

### F6 -- clang-tidy 21 had a false positive that 23 retired -- source-defect -- CLEARED (self)

The most interesting single result and not a defect in the candidate.

`bugprone-nondeterministic-pointer-iteration-order` fired at `src/main.cpp:382`, "sorting pointers is nondeterministic". After the bump it no longer fires. The code is unchanged and the check still exists in clang-tidy 23, confirmed by `--list-checks` and by re-running that check alone on that file, which reports zero.

The sort is `std::sort` over a vector of pointers with a comparator that compares **cell contents** and never a pointer value, so the order was always deterministic. **clang-tidy 21 was wrong and 23 is right.** This is the concrete return on currency that the section's last item asks to be honest about, and it is the one thing here that could not have been obtained by staying put.


**The +66 is attributed rather than waved at**, and the attribution is what makes the baseline raise safe: 49 from `bugprone-signed-bitwise`, 12 from `bugprone-unhandled-code-paths`, 4 from a widened `misc-use-internal-linkage`, 2 from `performance-faster-string-find`, minus the retired false positive. Every check that existed before reports the same count it reported before. Same code, same checks, same numbers.

**The 9.25 percent is recorded, not explained away.** Imports are unchanged, so nothing started shipping alongside the launcher; the executable itself grew. If a later section wants that back, this is the line that says where it went.

## Independent review

`codex review --commit 0227f4b` (gpt-6-astra, high effort) returned **one P2 and it was right**.

Its advantage was again probe construction, and this time the probe was a **partial** failure: CMake timing out while Ninja returned a newer tag. Every probe I had written was total, all-reachable or all-unreachable, and the bug lives only in the mixed case. That is the sixth section running where the reviewer found something by constructing a state I had not thought to construct.

The pattern across six sections is now specific enough to write down: **my probes test the states I designed for, and the defects live in the states I did not.** `§1`'s stamp outliving its executable, `§2`'s standalone extension build, `§4`'s third build in a sequence, `§5`'s analysis that could not run, and now a lookup that half worked.
