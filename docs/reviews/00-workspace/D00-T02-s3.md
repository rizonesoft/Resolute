## Findings

### F1 -- the section was the wrong shape, and the operator's question found it -- record -- CORRECTED by rewriting the section before implementing (independent) [minor]

Not a defect in code. The most valuable finding in the section and it came from a question, not a check.

The section was "House-Style Capture Store": screenshot five shipped AutoIt surfaces, commit the PNGs. The operator asked what a screenshot proved that the source did not. It does not:

```
AutoIt   GUICtrlCreateLabel($g_sProgName, $g_iSizeIcon + 22, 15, 300, 35)
C++      BASE_WIDTH = 200   BASE_ITEM_HEIGHT = 40   BASE_FONT_SIZE = 14
```

A PNG is a binary blob review cannot diff, it varies with the capturing machine, and nobody re-stakes one after a padding change. And the premise was already dead on its own terms: `AGENTS.md` says the UI is "rebuilt rather than reproduced", so an image of a surface the suite decided not to copy is a baseline for nothing.

**I had read both of those facts and built toward the screenshots anyway.** The `Fidelity:` citations say "against `docs/captures/house-style/`", and I treated the directory name as the specification instead of asking what the citation needed to mean.

### F2 -- the helper sent input to whatever had focus, and I had already said so -- adversarial -- FIXED in `f577fc9` (independent) [major]

Raised as a **P1**, and the worst finding in this file so far for a reason that is not technical.

`SetForegroundWindow` is refused by Windows when called from a background process. The helper called it, ignored the result, and sent keystrokes, which went to whichever application owned the foreground. During this section that was the operator's other editor session.

**The commit message described that happening and the code path stayed enabled.** Writing "this went wrong and I abandoned the approach" while leaving the approach in a committed script is the same class of defect as a check that reports success while doing nothing: the record and the artifact disagree, and the record is the one nobody executes.

Synthetic input is removed rather than gated. The helper also fails closed now: if the target does not own the foreground it refuses instead of copying whatever is on top, because an overlapping window filed as the target's evidence is worse than no evidence. Driven, exit 3, nothing written.

### F3 -- the cleanup could kill a process the operator already had open -- adversarial -- FIXED in `f577fc9` (independent) [critical]

Raised as a **P1**. An AutoIt tool launches a 32-bit stub that relaunches the `_X64` build and exits, so the process to capture is often not the one started. The fallback matched **by name**, and the cleanup then force-killed whatever it matched.

So a capture run could terminate a tool session the operator was using. That is `AGENTS.md`'s confirmed-destructive-action rule, broken by a helper whose whole job is to be passive.

Matching processes are now recorded **before** the launch, and only one that appeared afterwards is eligible to be captured or stopped. Driven with a pre-existing launcher running: it survives.

### F4 -- no target meant "capture the first window you find" -- adversarial -- FIXED in `f577fc9` (independent) [major]

Raised as a P2. With neither `-Path` nor `-WindowTitle`, the helper enumerated every windowed process and took the first, then foregrounded and saved it. On a machine somebody is using, that is a screenshot of unrelated work, which is the specific harm that had already occurred once in this section by another route.

Refused before anything is enumerated, exit 2.

### F5 -- a committed sidecar said 100% while the image was stretched at 150% -- correctness -- FIXED in `f577fc9` (independent) [major]

Raised as a P2, and it falsified evidence already in the tree.

`GetDpiForWindow` returns a DPI-**unaware** window's *logical* dpi, which is 96 even on a 150 percent display. The AutoIt capture's sidecar therefore read `96 (100% scaling)` for an image Windows had bitmap-stretched at 144. The sidecar exists to make the capture reproducible, and it was describing a different rendering than the one in the file beside it.

Both captures re-taken with both figures recorded, and the pair turns out to be **better evidence than either alone**:

```
AutoIt tool     monitor 144 dpi   window  96 dpi   aware=False
C++ launcher    monitor 144 dpi   window 144 dpi   aware=True
```

That is the DPI deviation this section is required to name, visible in the metadata rather than asserted in prose.

### F6 -- the plan named the section by a title it no longer had -- record -- FIXED in `f8cc708` (self) [minor]

`plan --check` enforces ref, status and item-count parity and **not** the Deliverable text, so the plan kept reading "House-style capture store" after the rewrite. The plan is what a person reads and pastes into a session, so a stale title there is a stale instruction. Worth knowing that the parity check does not cover it.

## What the contract actually buys

The test is the point, and it is worth being precise about why it is not just a second copy of the numbers:

```
Sidebar::BASE_WIDTH 200 -> 220, contract.md untouched
  CHECK( found->second == actual )
  with expansion: 200 == 220
  symbol := "Sidebar::BASE_WIDTH"
  check-all: tests FAILED
```

The test carries **no numbers**. Its table maps a contract row to its constant; the expected value is read from `contract.md` at run time. So the numbers live in the headers, the contract restates them for a reader, and the test proves the restatement is still true. Three tests, and the two supporting ones matter: one asserts the contract parses to something, because a contract parsing to nothing would let every other assertion pass vacuously, and one checks the reverse direction so a row naming a renamed constant cannot sit unchecked.

What is deliberately **not** covered is stated in the file rather than left to be discovered: colour, because the palette changes with theme and system accent; the type ramp, because a control passing a raw size is a defect for `D01 T02` rather than a value to enshrine; and rendering fidelity, which is `D01 T02 §5`'s.
