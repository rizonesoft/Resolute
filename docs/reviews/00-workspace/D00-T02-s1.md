## Findings

### F1 -- a defect `§5` already fixed, reintroduced here -- correctness -- FIXED in `c195629` (independent) [major]

Raised by the independent review as a **P2**.

`ctest --preset` reads `CMakePresets.json` from the **current** directory. Run from `scripts/`, the tests gate failed with `Could not read presets` while the tree was perfectly healthy.

**`D00 T01 §5`'s review found exactly this defect, for `cmake --preset`, and I fixed it for the launcher build alone.** The class stayed open, and this section walked into it two sections later with a different preset-consuming command.

**So the fix is not the one the reviewer proposed.** It suggested wrapping the `ctest` call in `Push-Location`, which is correct and is what `Build-Launcher` already does. Doing that would have closed the second instance and left the class open a third time. `check-all.ps1` now runs from the repository root **once, for every gate**, and that immediately caught a third instance nobody had reported: `plan --check` resolves its derived JSON under `build/` the same way.

```
before   from scripts/   tests FAILED, plan --check FAILED, 2 of 8
after    from scripts/   8 gate(s) ok
         from the root   11 gate(s) ok
```

A command whose whole promise is that it can always be run should not care where it is run from.

### F2 -- adding our own tests put 37 dependency findings into the baseline -- integration -- FIXED before committing (self) [major]

Caught by the gate itself on the first run after the suite landed: `206 finding(s), above the baseline of 169`.

The 169 were unchanged and **zero** were in `tests/`. All 37 were in `_deps/catch2-src/src/catch2/`.

`.clang-tidy` carried `HeaderFilterRegex: '.*[/\\](src|shared)[/\\].*'`, written to mean "this repository's `src` and `shared`". It matches **any** directory called `src` anywhere, and Catch2 keeps its headers in one. The tidy gate compounded it by filtering translation *units* by path and not *findings*, which was invisible for as long as every TU of ours included only our own headers.

Fixed where the number is computed: `check-all.ps1` drops any finding whose path contains `/_deps/`, whichever TU surfaced it, which is the by-construction exemption the warning policy already states. `llvm::Regex` has no negative lookahead, so the header filter cannot express "`src` but not under `_deps`", and that limitation is now written into `.clang-tidy` rather than left to be rediscovered.

**The gate caught this on its own**, which is the first time in this file that a check built by an earlier section found a defect in a later one without a human or a reviewer pointing at it.

### F3 -- the link failed because UNICODE propagates publicly -- source-defect -- FIXED before committing (self) [major]

`ld.lld: error: undefined symbol: WinMain`, referenced by `crtexewin.c`, mingw's **GUI** startup stub, on a console test binary.

`ResoluteUI_static` defines `UNICODE` and `_UNICODE` as `PUBLIC`, so Catch2 compiled its entry point as `wmain`. Without `-municode` the CRT looked for `main` or `WinMain`, found neither, and pulled the GUI stub.

Diagnosed by reading the archive rather than reasoning about it: `llvm-nm --defined-only libCatch2Maind.a` shows `T wmain` and no `main`. That took one command and removed the guesswork entirely.

The test target sets `-municode` and deliberately **not** `-mwindows`, because a test runner is a console program and needs its output on a console.

### F4 -- the tool tag is not printable, and the requirement was still met -- design -- CORRECTED in approach (self) [minor]

The item requires a failure to print "the tool tag, the expected value, and the actual value".

Catch2's console reporter prints **no tags**, at any verbosity, checked at `--verbosity high`. The first conclusion was that the requirement could not be met literally and the item should be corrected to say so.

That was wrong, and one more command showed it. `catch_discover_tests(... ADD_TAGS_AS_LABELS)` carries each case's tags through as **ctest labels**, and ctest prints labels in its failure summary:

```
The following tests FAILED:
    1 - PROBE: this test fails on purpose (Failed)        dpi ui
```

All three requirements land in one log. And a label is strictly more useful than a printed string, because it filters: `ctest --preset debug -L ui`.

**Recorded because the near-miss is the lesson**: the item was about to be narrowed to fit the tool, on the strength of one reporter's output, when the capability existed one layer up.

### F5 -- the checkpoint still named the preset its own first item had corrected -- record -- CORRECTED before implementing (self) [minor]

`D00 T01 §5` corrected `ctest --preset x64-debug` in this section's first item while wiring the test gate, and did not reach the `Test checkpoint` six lines below. The section carried the correction and the error simultaneously.

Worth recording as a pattern rather than a typo: a correction applied to the item it was noticed in, rather than to the section, is the same shape as F1.

### F6 -- a scratch file that was never a test -- consistency -- CORRECTED by deletion (self) [minor]

`test_font.cpp`, 30 lines at the repository root, tracked, built by nothing, `printf`ing DirectWrite metrics for Cascadia Mono with **no assertion of any kind**.

The item offered to keep it "as a real test if it still proves something". It does not: a test asserting a font has a particular height would pin the machine's installed font version rather than this suite's behaviour. Deleted with `git rm`, not gitignored, which is the cheaper substitute the item explicitly names.

## What the first tests were chosen to be

Not a placeholder. `Dpi::Scale` and `ScaleF` are what every control in the shared library routes its geometry through, and `DESIGN.md` requires every surface render correctly at every DPI with no hardcoded sizes.

The most useful case pins `MulDiv`'s round-to-nearest, which is invisible at 100% and visible on every odd value at 125%: `Scale(3, 120)` is 4, and truncation would give 3, losing half a pixel per control and accumulating down a stacked layout.

The read-back rule in `tests/README.md` is the convention that matters and is **not yet exercised**, because these functions are pure and have nothing to read back. It is written for `D00 T02 §2`'s fixtures, where destructive code first gets a disposable target. Saying so is better than implying the rule is proven.
