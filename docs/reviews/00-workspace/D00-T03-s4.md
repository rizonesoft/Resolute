## Findings

### F1 -- both superseded-file headers stated their own line count -- record -- FIXED

The header added to `TODO.md` said "728 lines"; the file was 743 lines once the header was in it. `TODO-ux.md` said 341 against an actual 348. Both figures were measured before the header was written and invalidated by writing it.

This is the **second occurrence of one defect class in this file**. `§2` hit it in the survivor table, where the intake TODO's own occurrence count changed by tabulating it, and that row was deliberately left without a number for exactly this reason. Recognising the shape once did not prevent repeating it two sections later.

`D00 T04 §2` states the rule for this situation: the second finding in a category raises the question of what check would have caught it. The answer here is concrete rather than procedural. **A figure about a file, written inside that file, cannot be stated safely; a figure about it written in a claim can**, because the claim is re-measured. So the line counts were removed and the stable figures kept as claims:

```
<!-- claim: count "\n- \[ \]" TODO.md = 348 -->
<!-- claim: count "\n- \[ \]" TODO-ux.md = 101 -->
```

Open-item counts are stable under editing a header; line counts are not. That distinction is the durable lesson, and both headers now say why no line count appears.

### F2 -- the claims checker silently drops a claim it cannot parse -- FILED to `D00 T04 §1`

Found while fixing F1. Writing those two claims produced a real newline inside the pattern rather than the two characters `\n`, which split each claim across two lines. `CLAIM_RE` matches within a single line, so neither half matched anything.

**Nothing was reported.** The total simply went from 30 back to 28 and still said "28 hold, 0 stale, 0 malformed". A claim that should have failed loudly instead vanished, and the summary line continued to read as a clean pass. That inversion is worse than a missing check: it is a check that reports success for its own absence.

A second, related limitation surfaced in the same attempt: `_check_count` compiles the pattern without `re.MULTILINE`, so an anchored `^- \[ \]` matches only at the start of the file and counts 0. It reports `STALE` rather than vanishing, so it is visible, but the grammar does not say so anywhere.

Both filed to `D00 T04 §1`, which owns the checker. Not fixed here: this section owns documentation, and changing the verification tool while using it to verify this section's own work would be circular.

### F3 -- `TODO.md` held one idea the plan does not cover -- routed, not a defect

Recorded because "superseded" is the moment ideas get lost silently, and the item's cheaper-substitute clause names deletion as the failure.

`TODO.md` devotes three phases and 51 mentions to hosting Control Panel applets: loading `.cpl` DLLs in-process and calling `CPlApplet`. `git grep -i "\.cpl"` over `todo/` returned **nothing**, so the Resolute plan has no coverage at all.

Filed as a decision on `D03 T01 §4` rather than as work, because whether the launcher should host third-party DLLs in its own elevated process is a product judgement, not an implementation detail. That section already plans to *open* Control Panel items by CLSID through the shell, which is a different and much safer thing, and the filed item says so, so nobody later mistakes one for the other.

### F4 -- there is no `LICENSE` file -- FILED to `D06 T01 §8`

Found while writing the README's licence section, which originally said "See `LICENSE`". `ls LICENSE*` returns nothing.

The repository is public, so every clone taken so far carries no grant at all. The README now states the position rather than pointing at a missing file, and names `D06 T01 §8` as the owner. The licence itself was deliberately not chosen here: the AutoIt suite ships GPL v3 and the C++ code came from repositories Rizonesoft owns outright, so it is a decision with consequences, and it is the operator's.

While filing it, the README's cross-reference was corrected from `D06 T01 §3` to `§8`; `§3` is installers.
